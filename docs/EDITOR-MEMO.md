# 에디터 사이클 메모 — 2026-11-12

> 이 문서는 **왜 다음 사이클이 필요한가**의 기록이다. 계획과 게이트는 `docs/EDITOR-PLAN.md` §12,
> 요구사항 문구는 같은 문서 §3에 있다. 여기에는 증거와 교훈만 둔다.
> 트리거: 사용자 불만 — "문서 편집기를 상상했다. 웹 UI 초보자에게는 너무 어렵다."
> 승인 문구: "html, css, js를 몰라도 문서 편집기처럼 고칠 수 있게."

## 1. 목표 대비 측정

**목표(계획 §1)**: 설정 패널에서 레이아웃·프레임·컴포넌트를 수정하면 실제 HTML/CSS로 저장된다.
**사용자가 말한 목표**: 문서 편집기처럼, 구현 언어를 모른 채 고친다.

UI 편집 도구의 능력 사다리:

| 단계 | 표면 | 이 저장소 |
| --- | --- | --- |
| 1 | 소스 텍스트 편집 | 가능(파일 직접) |
| 2 | 속성 인스펙터(요소별 폼) | **여기서 측정됨** |
| 3 | 렌더된 페이지 위 직접 조작 | 드래그 이동 1개뿐. 텍스트 편집 0 |
| 4 | 의도 서술("이걸 더 크게") | 없음 |

계획은 2단계용으로 세워졌고("설정 패널에서 수정"), 사용자는 3단계를 요구했다.
측정값(2026-11-12, `pages/play.html`의 `h1` 선택, 스타일 탭): 컨트롤 **18개** 중
**자유 텍스트 12개**(`clamp(1.9rem, 4vw, 2.8rem)`, `var(--hf-fg)`, `1px solid currentColor` 등),
select 6개, 색상 입력 2개. 사용자에게 보이는 CSS 속성명 **18개**(`color` … `grid-template-columns`).
그룹 제목은 화면 전체에서 **18개 중 영문 16개 · 한국어 2개**.
`contenteditable` 0개, 더블클릭 핸들러 0개, 리사이즈 핸들 0개.

손으로 한 결과와의 비교: **미측정**. `.hf/journal.jsonl`의 저장 4건은 전부 이 저장소 자신의 파일이다
(`index.html` 2회, `styles/play.css` 2회). 등록된 외부 프로젝트 0개. 외부 사용 기록이 없으므로
"손으로 하는 것보다 못하다"고 쓰지 않는다.

**같은 이유로 "어디서 막히는가"도 미측정이다.** 이 문서의 증거는 전부 렌더된 산출물 감사
(컨트롤 개수, 문자열, `contenteditable` 유무)이고, 초보자가 그 화면을 실제로 조작한 기록은 없다.
따라서 아래 교훈은 **증상의 원인 후보**이지 확정된 원인이 아니다. 이 구멍은 계획 §12의 G0이 맡는다 —
관측 1회가 어휘 축을 확정하거나 반증한다.

## 2. 재사용 가치가 있던 것 / 없던 것

- **있던 것**: 범위 치환 엔진(포맷 보존 테스트 42개), 노드 주소(`data-hf-node`)와 `setText` op,
  `.hf` 저널 Undo, 409 사전조건, 한국어 도움말 계약을 검사하는 e2e.
- **없던 것**: 사용자 어휘. 패널은 구현의 이름을 그대로 노출했고, 그것이 아래 교훈의 원인이다.

## 3. 교훈

각 교훈은 클래스 단위이며, 보고된 사례는 증거로만 붙는다.

### L1 — 작성 표면은 구현 언어를 요구하면 안 된다

- **도달 단계**: 액터(역할) — "목표는 있지만 구현 모델이 없는 사람".
- **사다리**: (1) 사례: 초보자가 제목을 키우려면 `clamp(1.9rem, 4vw, 2.8rem)`을 입력해야 했다.
  (2) 같은 표면의 형제들: 자유 텍스트 CSS 값 12개, 노출된 속성명 18개, 영문 그룹 제목 16/18,
  속성 편집기, `Matching rules` 선택자 목록. (3) 도구·제품·사람 이름 제거(detool):
  "작성 표면의 컨트롤이 구현의 어휘로 이름 붙으면, 사용자는 매 동작마다 의도를 구현으로 번역해야 하고,
  그 모델을 이미 가진 사람만 쓸 수 있다." (4) 액터 일반화: 위 문장 그대로.
- **경계(한 단계 위 반증)**: 필드 단계의 반례 후보 — 계획은 "손으로 쓴 것과 구분되지 않는 소스"를
  요구하고 README는 속성명을 일부러 보여준다(배우게 하려고). 반증되지 않는다: **보여주는 것**과
  **입력받는 것**은 다르다. 속성명은 muted `code`로 남기고, 컨트롤은 선택지로 만든다.
- **증거**: 스타일 탭 컨트롤 감사(컨트롤 18개 중 자유 텍스트 12개), `studio/panel.js`의 `field(..., property)` 렌더링.
- **형제(규칙이 미치지 못한 곳)**: 내용 탭의 Text 입력, 컴포넌트 옵션의 문자열 필드, 코드 위치 탭의
  HTML 속성 편집 — 모두 자유 텍스트다. 하나도 실패로 기록되지 않았다(같은 클래스, 미발화).
- **처방 P1**: 초보자가 가장 먼저 하는 5개 편집(제목 글자, 제목 크기, 이미지 교체, 여백, 요소 이동)은
  **값을 타이핑하지 않고** 끝나야 한다. 값 컨트롤은 페이지의 실제 값에서 만든 스케일(단위별 정렬)에서
  고르고, 스케일에 없는 값은 "직접 입력"으로 연다. 속성명은 muted `code`로 계속 보여준다.
- **반증 기록**: 가정 = 그 5개가 이산 선택으로 표현 가능하다. 실험 = 이 저장소가 실제로 쓰는 값을 센다
  (`styles/*.css`, `components/*/*.css`, `index.html`). 결과 = `font-size` 고유값 6개
  (0.78 / 0.8 / 0.85 / 0.9 / 1rem + `clamp()` 1개), `gap` 고유값 13개(0.15–2.5rem, 상위 2개가 7/13),
  `padding` 고유값 23개.
  **부분 확인**: 값이 적은 축(`font-size` 6개)은 프리셋으로 덮이지만 `gap`·`padding`은 13·23종이라
  고정 목록이 곧 "직접 입력"이 된다. → 처방을 "선택지만"에서 **"스케일에서 고르기 + 직접 입력"**으로
  고쳐 씀: 목록은 페이지의 실제 값에서 만들고, 목록에 없으면 직접 입력한다.
  실패 조건(breaks-where): 스케일 추출이 페이지마다 다른 단위(`rem`/`px`/`clamp`)를 섞으면
  목록이 순서 없이 늘어나 사용자가 다시 읽어야 한다 → 단위별로 묶어 정렬한다.
- **소유자**: `docs/EDITOR-PLAN.md` §12 게이트 G1 (다음 사이클을 짓는 에이전트가 읽는 곳).

### L2 — 텍스트는 보이는 자리에서 고친다

- **도달 단계**: 액터 — "구현 모델 없이 문서를 고치려는 사람".
- **사다리**: (1) 사례: 제목 글자를 바꾸려면 미리보기 클릭 → 내용 탭 → 입력 → Save = 4동작,
  그리고 "내용"이 글자를 담는다는 것을 추측해야 한다. (2) 형제들: 더블클릭 핸들러 0개,
  빈 상태가 트리를 가리키는데 트리는 코드 위치 탭 뒤에 숨음, 리사이즈 핸들 0개(드래그만 있음).
  (3) detool: "편집 대상이 화면에 보이는데도 별도 폼에서만 고칠 수 있으면, 사용자는 대상과 폼의
  대응을 매번 기억해야 한다." (4) 액터 일반화: 위 문장 그대로.
- **경계**: 필드 반례 후보 — 컴포넌트 내부에서 렌더된 요소는 페이지 파일에 없다. 클릭한 원소가
  컴포넌트 템플릿 안이면 인라인 편집을 열면 안 된다(브리지가 `origin`으로 이미 구분한다).
- **증거**: 브리지 `select()`의 `origin`/`data-hf-node`, `contenteditable` 0개.
- **처방 P2**: 미리보기에서 텍스트를 더블클릭하면 그 자리에서 입력하고, 저장은 기존 pending op 경로
  (`textOp` → `setText`)를 그대로 쓴다.
- **반증 기록**: 가정 = 인라인 편집이 페이지 의미를 바꾸지 않고 같은 op으로 접힌다.
  실험 = 실행함(스튜디오를 띄우고 미리보기 문서에서 `h1[data-hf-node]`를 골라
  `contenteditable="plaintext-only"`를 걸고 `textContent`를 바꾼 뒤 측정): 계산된 `font-size` 41.16px 유지,
  페이지의 `data-hf` 파운데이션 13개 유지, 본문 길이 +16자. **확인**.
  실패 조건: `edit.mjs`의 `setText`는 자식이 있는 노드에 `NOT_A_LEAF`를 던진다 →
  포인터 아래 **가장 깊은 leaf**를 해석해야 하고, 블록을 그대로 편집하면 저장이 거부된다.
- **소유자**: `docs/EDITOR-PLAN.md` §12 게이트 G2.

### L3 — 빈 상태는 보이는 것을 가리켜야 한다

- **도달 단계**: 액터 — "처음 열었고 아직 아무것도 선택하지 않은 사람".
- **사다리**: (1) 사례: 첫 화면의 안내문이 영문 "Select an element in the preview or the tree."인데
  트리는 코드 위치 탭을 열어야 보인다. (2) 형제들: 선택 전 탭 6개 중 3개만 보임, 정적 마크업의
  `aria-selected`(`스타일`)와 로드 직후 실제 선택(`내용`) 불일치, 빈 상태 문구가 영문.
  (3) detool: "안내가 존재하지 않거나 숨은 대상을 가리키면, 사용자는 지시를 따를 수 없고 화면이
  고장 났다고 읽는다." (4) 액터 일반화: 위 문장 그대로.
- **경계**: 필드 반례 후보 — 대상이 실제로 화면에 없는 편집(파일 경로, 선택자)은 문서로 안내해도 된다.
- **증거**: 선택 없이 로드한 측정 결과 — 보이는 탭 3개(`내용`, `페이지 레이아웃`, `코드 위치`),
  `aria-selected="true"`는 `tab-node`(내용), 보이는 패널 `panel-node`, 안내문 1개(영문),
  `#tree`는 행 116개를 이미 렌더했지만 `#tree-host`가 `hidden`이라 보이지 않는다.
  정적 마크업은 `스타일`을 `aria-selected="true"`로 두므로 로드 직후 상태와 어긋난다.
- **처방 P3**: 첫 화면에서 안내문이 가리키는 대상은 그 화면에 있어야 한다 — 트리를 기본 노출하거나
  문구에서 "tree"를 뺀다. 그리고 초기 선택 탭은 그 탭의 빈 상태가 실제로 보이는 탭과 일치시킨다.
- **반증 기록**: 가정 = 빈 상태가 초보자가 처음 읽는 문장이다. 실험 = 측정(선택 없이 스튜디오 로드).
  결과 = 컨트롤 0개, 안내문만 존재 → **확인**. 실패 조건: 트리를 기본 노출하면 좁은 화면에서
  미리보기가 밀린다 → 좁은 폭에서는 접힌 채로 두고 문구를 그에 맞춘다.
- **소유자**: `docs/EDITOR-PLAN.md` §12 게이트 G3.

### L4 — 한 표면 안에서 언어를 섞지 않는다

- **도달 단계**: 메커니즘(도구 이름 없음) — "한 표면의 라벨이 두 언어로 갈리면, 사용자는 각 라벨을
  서로 다른 어휘 체계로 읽고 매번 재해석한다."
- **사다리**: (1) 사례: 탭은 한국어, 그룹 제목은 영문 16개(`Owned by`, `Matching rules`, `Insert`,
  `Move`, `Wrap`, `Duplicate`, `Delete`, `Placement` …) 대 한국어 2개. (2) 형제들: 필드 라벨은
  한국어인데 속성명은 영문 코드(의도된 것), 빈 상태 문구는 영문.
  (3) detool: 위 문장. (4) 액터 일반화: 그대로.
- **경계**: 속성명은 의도적으로 영문 코드로 남긴다(L1의 경계와 같은 이유).
- **증거**: 렌더된 그룹 제목 18개 수집 결과 영문 16 · 한국어 2 (`페이지 골격`, `페이지 구조`),
  `tests/studio.e2e.test.mjs`의 라벨 감사는 `help`만 검사한다.
- **형제 규칙이 부분만 덮음**: N9("모든 탭·섹션 제목·설정 필드에 `?` 아이콘과 한국어 설명")는
  **설명**만 한국어로 요구하고 **제목 텍스트**는 요구하지 않는다. 그래서 영문 제목이 통과했다.
  새 규칙을 추가하지 않고 N9의 범위를 제목 텍스트까지 넓힌다.
- **처방 P4**: N9를 "제목 텍스트와 설명 모두 한국어"로 확장하고, 기존 라벨 감사 테스트가
  `title.textContent`도 한국어인지 검사하게 한다.
- **반증 기록**: 가정 = 그룹 제목은 계약이 아니라 라벨이다. 실험 = 테스트에서 제목 문자열 단언을 찾는다.
  결과 = `help`의 존재와 한국어 여부만 단언(`tests/studio.e2e.test.mjs:782–787`), 제목 텍스트 단언 없음 →
  **확인**. 실패 조건: `Matching rules (3)`처럼 개수를 담은 제목은 형식이 바뀌면 테스트가 같이 바뀌어야 한다.
- **소유자**: `docs/EDITOR-PLAN.md` §3 N9 (기존 규칙 확장).

## 4. 필드 점검

교훈 4개(≥3)이므로 실행. 저장한 출처와 인용 위치는 `docs/sources/README.md`에 있다:
`nng-heuristics.txt`(Nielsen 10 heuristics, 2024 개정), `nng-progressive.txt`, `mdn-css-basics.txt`.

| 출처 클래스 | 메모의 교훈 | 판정 |
| --- | --- | --- |
| #2 Match Between the System and the Real World | L1 | 일치 |
| #6 Recognition Rather than Recall | L2, L3 | 일치 |
| #4 Consistency and Standards | L4 | 일치 |
| #7 Flexibility and Efficiency of Use | L2(직접 조작이 빠른 경로) | 부분 일치 |
| (progressive disclosure) 점진적 노출 | L1의 경계 — 스케일을 먼저, 직접 입력은 뒤에 | 일치 |
| #1 Visibility of System Status | — | 필드 후보(기록에 사례 없음) |
| #3 User Control and Freedom | — | 필드 후보. Undo/저장 취소가 이미 덮음 |
| #5 Error Prevention | — | 필드 후보. 409·사전조건이 이미 덮음 |
| #9 Help Users Recognize, Diagnose, and Recover from Errors | — | 필드 후보(토스트 문구는 미측정) |

메모가 이름 붙이지 않은 클래스는 필드 후보로만 적는다. 기록에 사례가 없으므로 교훈이 아니다.

## 5. 안티패턴

- **어휘 누출**: 구현의 이름을 사용자 컨트롤 라벨로 쓴다. 게이트 G1.
- **폼 전용 편집**: 화면에 보이는 대상을 별도 폼에서만 고칠 수 있게 한다. 게이트 G2.
- **죽은 안내**: 안내문이 숨었거나 없는 대상을 가리킨다. 게이트 G3.
- **언어 혼합**: 한 표면의 라벨이 두 언어로 갈린다. 게이트 G4(N9 확장).

## 6. 처방을 접은 이유 / 재개 조건

- `crossthink` 생략: 처방 4개가 이미 2개 이상의 경로를 탄다(값 선택지, 직접 조작, 초기 상태,
  현지화). 한 경로에 몰려 있지 않으므로 매핑이 추가할 것이 없다.
- `elon`은 아래 표로 각 처방을 목표·출처·보관 비용에 대해 물었다. 삭제 제안 없음: 네 처방 모두
  각 교훈의 증거에 직접 대응하고, 하나를 빼면 해당 클래스가 게이트 없이 남는다.

| Item | Serves | Source | Holds | Bought | Orphans | Re-add | Verdict | Reason |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| P1 초보자 5개 편집에서 값 타이핑 제거 | L1 | 사용자 승인 문구, 2026-11-12 | yes | 자유 텍스트 12/18 중 기본 경로를 스케일 선택으로 대체, 13·23종 축은 직접 입력 유지 | 없음 | 낮음 | keep | 고정 목록이 직접 입력이 되는 축을 측정으로 확인해 범위를 좁힘 |
| P2 더블클릭 인라인 텍스트 편집 | L2 | 사용자 불만, 2026-11-12 | yes | 4동작 → 2동작 | 없음(`textOp` 재사용) | 낮음 | keep | 새 op 없이 leaf 해석만 추가 |
| P3 빈 상태가 가리키는 대상 노출 | L3 | 첫 화면 측정, 2026-11-12 | yes | 첫 화면 컨트롤 0 → 안내 가능 | 좁은 폭의 미리보기 공간 | 낮음 | keep | 문구 수정만으로도 성립 |
| P4 N9를 제목 텍스트까지 확장 | L4 | 렌더 제목 수집, 2026-11-12 | yes | 영문 16/18 제거 | 없음 | 낮음 | keep | 새 규칙이 아니라 범위 확장 |

- 접은 것 없음. 모든 처방이 실험을 통과했거나(부분 확인 포함) 통과하도록 고쳐 썼다.

## 7. 다음 사이클 첫 확인

**먼저 G0(관측).** 이 문서의 4개 교훈은 전부 산출물 감사에서 나왔고, 초보자가 그 화면에서 어디서
막히는지는 관측된 적이 없다. 편집 없이 띄운 빌드에서 사람 1명·15분 관측 1회가 P1–P4 전체를 선점한다.
막힘이 어휘가 아니면(탭 구조·조작·미리보기가 클릭 가능한지 모름) P1–P4는 같은 인스펙터의 재포장이므로
이 절을 다시 쓴다.

관측이 어휘를 가리키면 그 다음은 G2의 실패 조건이다: 더블클릭한 블록에 자식이 있으면 `setText`가
`NOT_A_LEAF`로 거부하므로, 포인터 아래 leaf 해석이 먼저 있어야 인라인 편집이 저장까지 간다.
이 확인 없이 UI부터 만들면 "편집은 되는데 저장이 안 되는" 상태가 된다.
